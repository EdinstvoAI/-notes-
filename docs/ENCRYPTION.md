# Шифрование — план

## Решение Макара (02.11.2026)

«Шифруем определённые заметки… то, что в облако, нет смысла шифровать, ну или можно предложить.
Мои данные зашифруй, отзови коммиты и зашифруй. А если данные не восстановить?»

- **Главное — закрытые заметки**, как в Apple Notes и Bear: человек выбирает заметки или папки,
  они шифруются на диске, открываются в приложении пинкодом или Touch ID. Остальное — обычные `.md`.
- **Файл закрытой заметки остаётся `.md`**: первая строка — понятная подпись «заметка закрыта
  в <notes>», дальше шифр (AES-GCM 256, CryptoKit). Имя файла видно (как заголовок в Apple Notes),
  текст — нет. На GitHub такой файл уходит уже шифром, отдельная схема не нужна.
- **Шифрование всей копии на GitHub** (раздел ниже) — не по умолчанию, предложить как опцию.
- **Его данные**: закрыть выбранные заметки и вычистить их открытые версии из истории git —
  локально и на GitHub (переписать историю, force push). Перед этим полная копия хранилища вне
  папки; GitHub ещё может держать старые версии в кэше — сказать прямо. Делается только по его
  отдельному «да» и со списком заметок от него.
- **Если ключ потерян**: ключ в Связке ключей (через iCloud — на второй Mac) и код восстановления,
  показанный один раз. Потеряны оба — закрытые заметки не открыть никому, это цена шифрования.
  Об этом предупреждаем при первом закрытии.

## Локально (02.11.2026, «хотел бы, чтобы шифровалось локально»)

Предлагаю: папка с заметками живёт внутри **зашифрованного образа диска macOS** (APFS, AES-256,
sparsebundle — штатный `hdiutil`, без зависимостей).

- Приложение открыто и разблокировано → образ подключён, внутри обычные `.md` и git: всё работает
  как сейчас, другие редакторы тоже открывают файлы.
- Приложение заблокировано или закрыто → образ отключён, на диске только шифр. Его же видят
  Time Machine и любые копии.
- Пароль образа — случайный, в Связке ключей; открывается тем же пинкодом и Touch ID.
  Код восстановления показываем один раз.
- Индекс поиска и кэш переезжают внутрь образа, иначе текст утечёт через них.
- Не отключается, пока файл держит другая программа: предупреждаем, отключаем, когда отпустит.

Отличие от правила «хранилище открывается любым редактором»: теперь только пока приложение
разблокировано. Это меняет запрет из CLAUDE.md, решение Макара.

Шифрование папки «файл за файлом» (`.md` → шифр) не предлагаю: ломает другие редакторы, git-историю,
поиск и слияние, а защищает не больше образа.

## Что защищаем

- **На Mac** — ничего не меняется: заметки — обычные `.md`, локальная история git — открытая.
  Диск защищает FileVault, приложение — пинкод и Touch ID.
- **На GitHub** — только шифр: ни текста, ни имён файлов и папок. Утёк репозиторий, украли токен,
  GitHub сам что-то читает — прочитать нечего.
- Видно останется: сколько файлов, их примерный размер, когда была отправка.

## Как устроено

Два репозитория вместо одного:

1. **Папка с заметками** — как сейчас: открытый git, коммиты раз в час, откат правок, слияние.
2. **Зеркало** — служебный репозиторий в `Application Support/<id>/encrypted/`, вне хранилища.
   Только оно уходит на GitHub.

**Отправка.** Берём последний коммит папки и для каждого файла делаем зашифрованный объект:
- имя объекта — `HMAC(ключ, путь)`, путь не виден;
- содержимое — AES-GCM 256 (CryptoKit), случайный nonce, путь внутри шифра;
- неизменённые файлы заново не шифруются: держим кэш «хеш текста → объект», и в истории
  зеркала остаются только реальные правки.

Плюс зашифрованная опись: какие объекты к каким путям, какой коммит папки это был.
Коммит зеркала с безличным сообщением «sync» → push.

**Загрузка.** fetch зеркала → расшифровываем опись и объекты → собираем из них обычный коммит
«их версия» в папке → дальше существующее слияние `GitVault.merge(theirs:)`: при конфликте
сохраняются обе версии, как сейчас. Пара «коммит зеркала ↔ коммит папки» запоминается
вне хранилища — это общая точка для следующего слияния.

## Ключ

- Один случайный ключ на хранилище, 256 бит.
- Лежит в Связке ключей как синхронизируемый: через iCloud сам приходит на второй Mac.
- **Код восстановления** — при включении показываем один раз (24 слова или 8 групп по 4 знака),
  просим сохранить. Ключ, завёрнутый этим кодом, лежит в зеркале. Второй Mac без iCloud Связки
  вводит код один раз.
- Потерян ключ и код — копию на GitHub не открыть никому. Заметки на Mac при этом целы.

## Включение (важное)

- В старом репозитории на GitHub вся история уже открытая. Шифрование включаем **в новый**
  приватный репозиторий, старый предлагаем удалить — и прямо говорим, что пока он есть,
  открытая история в нём остаётся. Удаляет человек сам, по ссылке.
- Выключить можно: зеркало перестаёт отправляться, новое заводится открытым — только по явному выбору.

## Проверка (тесты в NotesCore)

- шифр → расшифровка дают исходные байты, картинки тоже;
- в объектах зеркала нет ни строчки текста и ни одного пути;
- чужой ключ и испорченный объект — ошибка, а не мусор в заметке;
- два Mac и «GitHub» как локальный bare-репозиторий: правки с обеих сторон, конфликт → обе версии;
- повторная отправка без правок не создаёт новых объектов.

## Объём

Примерно 3–4 дня: шифр и ключ — день, зеркало и отправка — день, загрузка и слияние — день,
экраны включения и кода восстановления (рисует Макар) и проверка вживую — остальное.
