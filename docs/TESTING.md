# Тесты и проверка

Что и как проверять перед сдачей. Порядок сдачи — в [CLAUDE.md](../CLAUDE.md).

## Тесты

Логика без UI живёт в пакете `NotesCore` и тестируется Swift Testing, без Xcode:

```bash
cd NotesCore && swift test
```

Распознавание речи — в `NotesSpeech`. Тесты с настоящими моделями включаются переменными, потому что
модели весят сотни мегабайт:

```bash
cd NotesSpeech && NOTES_GIGAAM_DIR=<папка распакованной GigaAM> swift test
```

`NOTES_WHISPER_TEST=1` дополнительно качает Whisper small (464 МБ) и распознаёт ту же запись.

Сейчас покрыто: git в папке (init на ветке main, .gitignore, коммиты, пустые коммиты, push в
локальный bare-репозиторий) и GitHub (разбор кода, ожидание, slow_down, истёкший код, отказ,
создание notes и уже существующий notes), синхронизация (подпись коммита, пустых коммитов нет,
отправка раз в сутки и только если есть что отправлять), слежка за папкой и pull с двумя «Маками»
(догнать сервер, слияние, конфликт — обе версии, правка сильнее удаления, второй Мак с чужой историей)
пинкод (придумать и повторить, несовпадение, только цифры, хеш с солью), умный вход
(перезапуск в течение 5 минут, 15 минут в фоне, пауза после 5 ошибок, пауза переживает перезапуск)
и горячая клавиша (подпись, порядок ⌃⌥⇧⌘, без модификатора нельзя, системные сочетания, хранение). Сеть в тестах
подменяется (`HTTPClient`), в GitHub не ходим; «сервер» для push — bare-репозиторий во временной папке.

- Описание теста в `@Test("...")` и комментарии — по-русски: тест читается как описание поведения.
  Имена файлов, типов и функций тестов — по-английски, как во всём коде.
- В комментарии пиши, что именно ломалось раньше. Иначе через месяц тест выглядит придиркой, и его удаляют.
- **Новый тест проверяется поломкой.** Сломай то, что он охраняет, убедись, что он упал, и верни как было.
- Новую логику — в `NotesCore`, а не во вьюхи: там её можно проверить.

## Живая проверка

- Своё приложение запускай из `build/` и закрывай **только свои процессы** (по пути `build/…`), не по имени:
  Макар часто тестирует параллельно из Xcode, и `pkill -x "<notes>"` убивал его запуск (19.10.2026).
- Запускай в фоне — `open -g -n -F "build/…/<notes>.app" --args -testVault YES …` — снимок по номеру окна
  (`screencapture -o -l`) берётся и из-под других окон; после снимка сразу `kill <PID>`, самопроверку тоже.
- Нажатия клавиш и клики скриптом macOS не пропускает без доступа, а доступ — системная настройка Макара.
  Состояния экранов снимаем отладочными флагами (`-onboardingStep`, `-pinPreview`, `-dictationTestFile`,
  `-speakerPreview YES -notesSection video` — разговор двух голосов со спикерами, сам убирается через 40 с),
  а живые нажатия (хоткей, ввод с клавиатуры, Touch ID) просим проверить Макара и так и пишем.
- Язык: `-AppleLanguages '(en)'` или `'(sr-Latn)'`. Мимо экрана входа (если у Макара стоит пинкод):
  `-lock.lastSeenUnlocked "<date>$(date -u +%Y-%m-%dT%H:%M:%SZ)</date>"` — только для этого запуска,
  его настройки не меняются. `-testVault` принимает `YES`, не путь: с путём откроется его хранилище.
- Тестовые данные, которые трогают его настоящие (пинкод, токен), после проверки возвращаем как было
  или прямо говорим, что поменялось.

- Тест настоящей разметки спикеров: `DIARIZATION_MODELS=<папка с speakers/segmentation.onnx и embedding.onnx>
  swift test --filter Diarization` в NotesSpeech; без переменной пропускается.

## Поиск по смыслу

- Тест с настоящей моделью Apple: `cd NotesCore && NOTES_APPLE_EMBED=1 swift test --filter AppleEmbedderTests` —
  4 запроса без общих слов с заметками, планка «3 из 4». Упадёт ниже — пора на скачиваемую модель.
- Правка событий календаря (перенос, растягивание, имя, удаление, ⌘Z) — `editSelfTest` в `-liveSelfTest`:
  временный календарь, после — удаляется. Живая проверка календаря трогает только то, что создала сама (31.10.2026).

## Проверки Tauri (09.11.2026)

`cd desktop && npm run build` — TypeScript и Vite; `cargo test -p notes-core` — Rust-ядро;
`cargo build -p notes-desktop` — настоящее приложение для текущей ОС. На macOS требуется Xcode
с FoundationModels (SDK macOS 26+): системный мост компилируется при сборке Rust.

Для собственного Debug-запуска задавай `NOTES_TEST_ROOT` абсолютным путём во временной папке:
настройки идут в config/, расшифровки и модели — в data/, сейф и namespace пинкода тоже отдельные.
Не подменяй HOME. Перед запуском положи путь тестового хранилища в config/vault-path.
`NOTES_SELFTEST=1`, `NOTES_NO_CALENDAR=1`, `NOTES_SELFTEST_LOG` — сценарий настоящего окна,
без изменения календарей человека. Исполняемый файл запускай из собственной копии в build/,
через `open -g -n --env …`; самопроверка завершает только этот процесс.
Не запускай самопроверку пинкода без `NOTES_TEST_ROOT`: она ставит и удаляет тестовый пинкод.

Разделы сгенерированного текста проверены тестами Rust, включая сохранение frontmatter и текста,
замену только своего раздела и отсутствие дублей. Проверка поломкой: вставка «Кратко» в начало
вместо места после frontmatter ломает тест, после восстановления весь набор проходит.
